Consumer Preferences modal: 5 redesign options

Every option uses the same 20 sample products. Each tab shows the redesign, what changed, why it's better, and what it costs. The numbers refer to the problems below.

What's not working in the current modal

  1. The header and description use about 170px, so the grid gets about 60% of the modal and fewer than 3 full rows fit.
  2. The attribute chips aren't visibly linked to the "Values" dropdown. Which attribute is "Warm Colors" a value of? Are the chips filters?
  3. In a visual catalog, photos are only 100px and titles get cut off ("Performance tank in Terraco…").
  4. The stated goal is to "spot gaps in the assortment", but a grid only shows what exists. Missing items are invisible.
  5. There's no search or sort, and "64 Items" has no context: 64 out of how many, matching what?
  6. It's unclear what "New Attribute Collection" is made from: everything, the filtered items, or a selection?

What changes

  • The header is one line, and the description shrinks to a single muted line
  • Each filter is one pill showing Attribute: Value, so the separate Values dropdown is gone
  • Image-first vertical cards in 6 columns
  • Search, a result count and sort sit together in one toolbar

Why it's better

  • 1The grid gets about 75% of the height instead of about 60%, so roughly 2 more rows show without scrolling.
  • 2"Color: Warm colors" reads as a sentence, so you can't misread which value belongs to which attribute. Unset attributes show "Any".
  • 3Photos grow from 100px to about 170px. For a colour and pattern catalog, the image is the content.
  • 5"16 of 20 products" next to the filters says exactly what you're looking at.

Trade-offs

  • Long product names wrap to 2 lines under the image instead of beside it
  • With many attributes, the pill row needs to overflow into a "+3 more" menu

Best when: you want the smallest change for the biggest gain. It keeps the current structure and fixes density and clarity.

What changes

  • The attributes move into a left sidebar, each with its own checkbox values
  • Every value shows a live count, and values with 0 products are flagged in red
  • Presets like "Warm colors" become one-click shortcuts that tick a set of values
  • Active filters are repeated as removable chips above the grid

Why it's better

  • 2Each attribute's values sit directly under it, so how attributes and values relate is obvious and you can pick several values.
  • 4Counts show how deep the assortment is before you click. "Pink (1)" and "Linen (0)" point out gaps as you browse.
  • 5Shoppers know this pattern from e-commerce faceted search, so there's nothing new to learn.
  • "Warm colors" stays available, but it's clear which colours it includes.

Trade-offs

  • The sidebar costs about 250px of grid width (5 columns instead of 6)
  • Needs a collapse toggle on smaller screens

Best when: people filter by several attributes at once. This is the strongest general-purpose option.

What changes

  • A new "Coverage" view crosses two attributes, product type × colour family
  • Each cell shows thumbnails and a count. Thin cells (1 item) are amber and empty cells are hatched as gaps.
  • Rows and columns can be set to any attribute (Material × Function, and so on)
  • Clicking a cell filters the grid view to those products

Why it's better

  • 4This is the only option that makes missing products visible, which is the modal's stated purpose. At a glance: no neutral outerwear, no red bottoms, and bras only in pink.
  • Merchandisers can act on gaps right away ("+ Add" in an empty cell) instead of working them out from a list.
  • It turns a product dump into an assortment-planning tool, which competitors' basic grids don't offer.

Trade-offs

  • Needs a second view, so it can't be the only view
  • Attributes with many values (20+ colours) need grouping into families

Best when: the main users are designers or merchandisers planning the range. Ship it as a view toggle alongside option 1 or 2.

What changes

  • A grid/list toggle, with list showing a sortable table
  • Each attribute value gets its own column (Category, Color, Material, Function)
  • A sticky header row and checkbox selection

Why it's better

  • 2The attribute chips finally show their values for each product instead of being abstract tags.
  • 5Sorting by any column (click a header) and scanning SKUs is far faster than reading cards.
  • What you see matches what "Export as CSV" produces, so there are no surprises in the file.
  • About 12 rows fit on screen, versus about 6 cards today.

Trade-offs

  • Thumbnails are small, so it's weaker for judging colour and pattern
  • Should be offered as a toggle, not a replacement for the grid

Best when: online store or ops teams audit attributes and SKUs. It's cheap to add next to any other option.

What changes

  • The centred modal becomes a full-height side panel, so the page behind stays visible
  • Cards can be selected (checkbox appears on hover, with shift-click for ranges)
  • The footer becomes a selection bar: "4 selected · Export 4 · Create collection (4)"

Why it's better

  • 6"New Attribute Collection" now has a clear input, the items you picked, and the button says how many.
  • 1Full height gives about 90px more vertical room than the modal, and the panel can be resized.
  • Export can be scoped too: all items, filtered items or selected items.
  • A side panel suits "look something up, then go back" tasks better than a blocking modal.

Trade-offs

  • Selection adds state to manage (keeping it across filter changes, "select all 16")
  • Less of the page behind is visible on narrow laptops

Best when: building collections from the catalog is the main job. The selection pattern can also be added to options 1–4.
